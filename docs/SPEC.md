# ChillTransfer — Спецификация v0.1 (черновик на согласование)

## 1. Проблема и цель
Флеш-накопители большой ёмкости (64–256 ГБ) при копировании больших файлов сильно нагреваются; у многих нет встроенной защиты от перегрева → деградация NAND/контроллера, риск потери данных. Цель: контролируемая запись с паузами по температуре или по циклу «работа/отдых», в ущерб скорости ради ресурса накопителя.

## 2. Целевые платформы
- Windows 10/11 x64
- macOS 12+ (Apple Silicon и Intel)
- Linux: Ubuntu 20.04+ / Debian 11+, x86_64 (aarch64 — nice-to-have)

## 3. Функциональные требования

### FR-1 Выбор устройства
- Список съёмных накопителей (USB-флешки, внешние SSD/HDD). Внутренние диски — по умолчанию скрыты, с опцией «показать все».
- Для каждого: имя/метка, ёмкость, свободное место, файловая система, наличие датчика температуры («датчик обнаружен» / «не обнаружен»).
- Пересcan при hotplug (подключение/отключение) + кнопка ручного обновления.

### FR-2 Drag & Drop
- Перетаскивание файлов и папок из файлового менеджера ОС в окно → добавление в очередь.
- Дополнительно: кнопки «Добавить файлы» / «Добавить папку» (нативные диалоги).
- Очередь: список элементов с размером и статусом; удаление/перестановка до старта.

### FR-3 Движок копирования
- Рекурсивное копирование папок с сохранением структуры и метаданных (timestamps).
- Прогресс: общий %, текущий файл, скорость, ETA.
- Управление: Старт / Пауза / Продолжить / Стоп (отмена остатка очереди).
- Существующие файлы: по умолчанию пропуск при совпадении size+mtime; опции «перезаписать» / «пропустить все».
- Ошибки: ошибка на файле → пометить и продолжить (опция «остановиться на первой ошибке»); итоговый отчёт.
- fsync после каждого файла — целостность при случайном выдёргивании.

### FR-4 Термический контроллер (режим с датчиком)
Доступен, если для выбранного устройства обнаружен датчик:
- Параметры: T_pause (по умолч. 50 °C), T_resume (по умолч. 42 °C — гистерезис), интервал опроса (по умолч. 3 с).
- Логика: temp ≥ T_pause → пауза; temp ≤ T_resume → возобновление.
- Живой индикатор температуры и состояния.

### FR-5 Циклический режим (нет датчика / принудительно)
- Параметры: время работы W (по умолч. 10 мин), время отдыха R (по умолч. 5 мин).
- Логика: копировать W → пауза R → повторять до завершения.
- Можно включить вручную даже при наличии датчика («не доверяю датчику»).

### FR-6 Профили устройств
- Настройки сохраняются per-device (по серийному номеру/метке): режим, пороги/тайминги; восстанавливаются при повторном выборе устройства.

### FR-7 Статус и журнал
- Машина состояний: `idle → copying ⇄ paused_thermal | resting → done | error | cancelled`.
- Журнал событий (старт/пауза/возобновление/ошибки) с таймстампами, экспорт в файл.

## 4. Обнаружение датчика температуры (best-effort)
| Платформа | Метод |
|---|---|
| Windows | HID-датчики температуры (USB Temperature Sensor Class, usage page 0x02) через SetupAPI/HID API; корреляция с выбранным диском по USB-пути родительского устройства. Не найдено → «нет датчика». |
| Linux | `/sys/class/hwmon/*` для устройств, связанных с целевым блочным устройством; fallback — `smartctl -d usbsmart/sat`. |
| macOS | IOKit: запрос свойств температуры у IOService USB-устройства. Нет → «нет датчика». |

Ключевое: большинство флешек **не** выводят температуру вообще → циклический режим — основной сценарий, сенсорный — расширение при наличии. UI обязан явно показывать активный режим и причину (датчик найден / не найден). Обнаружение датчика никогда не блокирует запуск приложения.

## 5. Значения по умолчанию
- T_pause = 50 °C, T_resume = 42 °C, опрос = 3 с; W = 10 мин, R = 5 мин.
- Диапазоны: T — 30…80 °C (T_resume < T_pause), W/R — 1…60 мин.

## 7. Нефункциональные требования
- Нативный вид на каждой платформе (системные шрифты, светлая/тёмная тема).
- Без прав администратора/root для базового сценария; если чтение датчика требует привилегий — подсказка + graceful fallback в циклический режим.
- Низкое потребление CPU в простое (<1%).
- Локализация: RU + EN (см. вопрос владельцу).
- Лицензия GPL v3 (уже зафиксирована в репозитории).

## 8. Границы v1 / последующие версии
**v1:** FR-1…FR-7, один целевой накопитель, только запись на него.
**Потом (v1.x):** SHA-256 верификация после копирования, возобновление прерванных копий, троттлинг скорости вместо полной паузы, несколько целей одновременно, чтение с флешки с паузами.

## 9. Риски
| Риск | Митигация |
|---|---|
| Низкая доступность датчиков температуры | Циклический режим — основной путь; UI явно показывает активный режим |
| Выдёргивание во время записи | fsync на файл + предупреждение при отключении устройства, к которому идёт запись (best-effort) |
| Права доступа к чтению температуры (macOS/Linux) | Graceful degradation в циклический режим |
| Разные файловые системы (exFAT/FAT32/ext4/APFS) | Тест-матрица по ФС; ограничение 4 ГБ на FAT32 — предупреждение |
